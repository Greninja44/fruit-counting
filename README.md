# Fruit counting with computer vision

Detect, segment, count and (in video) track fruit with YOLO-family models, and evaluate everything against
human ground truth. Detection (Approach A) and instance segmentation (Approach B) share one model interface,
one dataset loader and one evaluation pipeline, so they can be compared on the same held-out test images.

Status and measured results: **[`outputs/reports/benchmark.md`](outputs/reports/benchmark.md)** (regenerated by
`scripts/evaluate.py`; nothing in it is hand-entered). Analysis of the results: [`docs/error_analysis.md`](docs/error_analysis.md).

## Layout

```
configs/default.yaml        all settings (classes, thresholds, model weights, paths)
src/fruitcount/
  data/                     dataset.py (YOLO parsing, group-aware splits), validate_dataset.py
  detection/                detector.py, segmenter.py, yolo_base.py, preprocess.py (CLAHE/gamma/tiling), factory.py
  tracking/tracker.py       unique-track counting, IoU tracker; ByteTrack via Ultralytics
  counting/                 counter.py (filtering, class-wise counts, video counter), video.py
  evaluation/               metrics.py, error_analysis.py, tags.py, runner.py, report.py
  visualization/draw_results.py
scripts/                    prepare_data, validate_dataset, tag_conditions, train, predict_image, predict_video,
                            evaluate, benchmark, crosscheck_coco_eval
app.py                      Gradio demo
tests/                      pytest (mock model; no weights/GPU/network needed)
docs/                       dataset_setup.md, evaluation.md, error_analysis.md
```

## Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e .
```

On an NVIDIA **Jetson**, install the JetPack-matched `torch`/`torchvision` first (the generic PyPI wheels are CPU-only
or the wrong CUDA build); the rest installs normally. GPU is optional: pass `--device cpu`.
Pretrained weights (not committed) go in `models/`:

```bash
cd models && for m in yolo11n yolo11s yolo11n-seg yolo11s-seg; do
  curl -LO https://github.com/ultralytics/assets/releases/download/v8.3.0/$m.pt; done
```

## Commands

| Task | Command |
|---|---|
| Prepare dataset (COCO apple/orange/banana test split) | `python scripts/prepare_data.py --coco-split val2017` |
| Validate annotations + stats + leakage check | `python scripts/validate_dataset.py --out outputs/reports/dataset_summary.json` |
| Condition tags for robustness subsets | `python scripts/tag_conditions.py` |
| Count fruit in an image / folder | `python scripts/predict_image.py --source path --approach detect` (or `segment`) |
| Count fruit in a video | `python scripts/predict_video.py --source clip.mp4 --mode frame` or `--mode track` |
| Fine-tune | `python scripts/train.py --approach detect --data data/processed/coco_fruit/dataset.yaml --epochs 50 --device 0` |
| Evaluate on the annotated test split | `python scripts/evaluate.py --approaches detect segment` |
| Robustness (illumination / small objects) | `python scripts/evaluate.py --approaches detect segment --preprocess none clahe gamma tile` |
| Evaluate fine-tuned weights | `python scripts/evaluate.py --approaches detect --weights runs/fruit_detect/weights/best.pt --tag finetuned` |
| Speed benchmark | `python scripts/benchmark.py --batch-sizes 1 4` |
| Demo app | `python app.py` (http://localhost:7860) |
| Tests | `python -m pytest` |

Common options: `--conf`, `--iou`, `--imgsz`, `--device {auto,cpu,cuda:0}`, `--config path.yaml`, `--weights`.
Invalid/corrupt images or videos and missing weights produce a clear error message and a non-zero exit code
(a corrupt file inside a folder is skipped with a warning).

## Counting semantics (important for video)

* **Image count** = detections with confidence >= `--conf` after NMS, total and per class.
* **Video, per-frame mode**: fruits *visible* in each frame. Nothing is accumulated.
* **Video, track mode** (ByteTrack by default): additionally reports **unique tracked fruit** = distinct track IDs that lived for
  at least `tracking.min_track_frames` frames. This is an *estimate*: it assumes limited occlusion and a camera that does not
  revisit the same fruit; a long occlusion splits one fruit into two IDs (over-count), ID switches or merged tracks under-count.
  The sum of per-frame counts is never presented as a number of unique fruits, and `unique_tracked` is `null` when tracking is off.

## Fine-tuning

`scripts/train.py` wraps Ultralytics training with the config's seed, saves checkpoints/logs/`args.yaml` under `runs/<name>/`
and copies the project config. Train on a machine with a real GPU (the data and scripts are the same); then evaluate with
`--weights` and `--tag`. Fine-tuned models use your own class names directly (no COCO class map is needed).
For frame sequences, split by video/sequence (see `docs/dataset_setup.md`) to avoid leakage.

## What is measured vs pending

See `outputs/reports/benchmark.md`. In short: the COCO-pretrained baselines are evaluated on a real, human-annotated, held-out
COCO test subset. **Not done here:** fine-tuning (no training on the Jetson; requires a GPU workstation), evaluation on
orchard/farm imagery, manual occlusion/background/viewpoint tags, a verified video ground truth for unique-count accuracy.
Those are marked *Pending* / *Not evaluated* in the reports, never filled with invented numbers.
